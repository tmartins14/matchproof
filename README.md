# Matchproof

**You want an AI narrator? It has to pass this test first.**

Narrator Trials puts candidate narrator models through the same exam: six seeded matches, each with traps planted in it (a red card on the hour, a stoppage-time penalty, a lead that changes hands late). Every narrator writes a claim for every key moment, and one fixed referee checks every claim against computed facts. The result is a league table, a side-by-side view of how each narrator handled the same moment, and a live desk where you can put a cleared narrator on air.

### How the referee works

- **Code first.** Every number and name in a claim is reconciled against the computed fact registry before any model reads the sentence. A claim that cites a fact it was not given, or one that does not exist, fails here.
- **A judge reads the wording.** `gpt-5-mini` decides whether the wording stays within what the cited facts say. Each claim ends STANDS, AMENDED or OVERTURNED; a model that does not answer a moment is HELD and scores 0.
- **An auditor checks what stood.** `grok-4.7` re-checks settled claims. If it disagrees, the judge is asked again with its reason, and the verdict on air after that consensus is the one that counts.

The referee is the same for every narrator, and no model produces a number: Python computes, the models orchestrate and narrate, the browser draws.

### Run the pack

```bash
make setup                                                              # uv sync, npm ci
az login                                                                # model access uses managed identity or az login
uv run python -m evals.trials --candidates gpt-5-mini --fixtures fx-01  # a one-fixture smoke
uv run python -m evals.trials                                           # all of pack-v1, every candidate
uv run python -m evals.trials_web evals/reports/trials/pack-v1.json     # the web export
uv run python -m scripts.record_fixtures                                # the cached Desk streams
make web-dev                                                            # http://localhost:3000
```

The pack is `evals/trials/pack_v1.yaml`, the candidates are `trial_candidates` in `packages/agents/config/models.yaml`, and the results are `evals/reports/trials/pack-v1.json`.

### Known limits

- The matches are synthetic. The generator uses a reduced rulebook: no offside rule in the engine (the player positions keep attackers onside at the pass), no substitutions, no own goals, and simplified fouls.
- Each candidate was run once on the pack. There are no repeats and no estimate of run-to-run variance.
- `grok-4.7` is also the auditor, and its narrator run is incomplete (14 of 85 moments unanswered, every one an `APITimeoutError` at 60 s; it scored 207 on the rest), so it is not ranked. `phi-4-mini` lost 68 of 85 moments (22 unanswered, 46 rejected by the claim store).

## How the full system works

1. **Compose.** Tactics (formation and three dials per team, plus a storyline) or a free-text brief go to the Composer agent, which produces a `MatchBrief`.
2. **Generate.** A seeded Python generator emits a full match: about 2,500 events plus 5 Hz positions for all 22 players.
3. **Compute.** Extractors turn events into facts. Every fact lists its source event IDs. No LLM touches the numbers.
4. **Narrate and check.** The Producer ranks key moments. The Narrator writes claims from facts only. The Checker reconciles every number in code, then judges the wording. On screen, each claim shows CHECKING, then STANDS, AMENDED or OVERTURNED.
5. **Render.** A live desk shows the pitch, timed overlays, the narrative feed and an evidence rail for every claim, in Fan, Analyst or Producer mode, in English or Spanish, in a Broadcast or Editorial theme.
