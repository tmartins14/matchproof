# Matchproof

**Set the tactics. Watch the match. Every claim proven.**

Matchproof composes a synthetic, football-realistic match from a tactical brief, streams it live, and explains it beat by beat. Every sentence it publishes links to a computed fact and the event IDs behind it. A Checker lets each claim stand, amends it or overturns it before it reaches the screen. Because the match comes from tactics you set, the same setup always produces the same match, so every claim can be tested against known ground truth.

Built for the Microsoft × Premier League *Inside the Game* Developer Hackathon (Oct 2026). All clubs, players and match data are fictional and generated by this repo.

- Live demo: https://matchproof.tylermartins.com (not deployed yet)

## How it works

1. **Compose.** Tactics (formation and three dials per team, plus a storyline) or a free-text brief go to the Composer agent, which produces a `MatchBrief`.
2. **Generate.** A seeded Python generator emits a full match: about 2,500 events plus 5 Hz positions for all 22 players.
3. **Compute.** Extractors turn events into facts. Every fact lists its source event IDs. No LLM touches the numbers.
4. **Narrate and check.** The Producer ranks key moments. The Narrator writes claims from facts only. The Checker reconciles every number in code, then judges the wording. On screen, each claim shows CHECKING, then STANDS, AMENDED or OVERTURNED.
5. **Render.** A live desk shows the pitch, timed overlays, the narrative feed and an evidence rail for every claim, in Fan, Analyst or Producer mode, in English or Spanish, in a Broadcast or Editorial theme.

## Status

Day 6 of 10 (Oct 22). The walking skeleton is deployed on Azure: a Container App calls a Foundry model with managed identity (M1). Positioning revised after reviewing the field; the voice guide and voice lint are in (`docs/VOICE.md`, `voice/banned.yaml`, enforced in `make lint`); the match generator v1 produces a seeded, full match of events with the brief's planted beats (`python -m sim generate`); calibrated against sourced league-level bands and reference means, including team shape (back-line height, length, width, compactness) measured by `sim/geometry.py` (`make calibrate`), with 22-player positions at 5 Hz and a freeze frame per event; `packages/intel` turns events and frames into facts with display renderings and source ids: per-team event and shape facts per window, half and match, sequence, shot, card and freeze-frame facts, and on-demand "since X" and change facts (`python -m intel facts`); batch and incremental extraction give the same registry. The beat detector (`intel/beats.py`: goals by kind, high-turnover and big chances, red cards, territorial spells, and a 15-minute momentum follow-up after every goal and red card; live and batch give the same beats) feeds the live SSE stream, played back as condensed live: the pipeline runs 120 match seconds ahead on a worker thread, cruises at 1, 3 or 6 match minutes per real second, slows to 1x with every frame around each goal, chance and red card, and holds 6 s on its freeze frame (`POST /matches`, `GET /matches/{id}/stream?speed=`, `GET /matches/{id}/facts/{fact_id}`, `python -m intel beats`). The match-data MCP server (`packages/mcp_match`, ADR 0008) is in: seven read tools plus `put_claims`, which only the in-process internal server has; the public read-only server is at `/mcp` (60 requests per minute per client), and a running match is queryable while it streams. The API container is now 1 vCPU and 2 GiB, and a fourth concurrent stream gets 503 with a cached-replay fallback body. The public MCP endpoint now answers `GET` and `DELETE` with 405 and shows only what viewers have already seen, while the internal server keeps the lookahead.
