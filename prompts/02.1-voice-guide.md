# Build prompt 02.1 — Voice guide and voice lint

**Mode:** code. **Budget:** about 1 hour. **Branch:** `chore/voice-guide`. **Depends on:** prompt 02 merged. **Lands before:** prompt 03.

## Context

Read `CLAUDE.md`, the Positioning section of `docs/PLAN.md`, `docs/SPEC.md` (modes: fan, analyst, producer), `schemas/beat.schema.json` (beat kinds), `schemas/claim.schema.json` (verdicts) and `docs/prototype/README.md`.

Matchproof puts generated text on screen for the whole match. If it reads like a chatbot, the product loses on presentation, and the verification story is weaker, because judges stop trusting text that sounds generated. This task makes "does not sound like AI" a written, testable requirement:

- a voice guide,
- a banned-pattern list kept as data,
- a deterministic lint that later prompts wire into the Narrator, the Checker and the evals,
- an example file that Tyler fills with 10 to 15 hand-written commentary lines.

It also fixes the on-screen verdict vocabulary to football's own review language instead of AI language.

Before writing: restate the task back in six lines or fewer and wait for my go.

## Seam rules

- The lint is pure, deterministic Python. No LLM calls, no network.
- The verdict enum in `claim.schema.json` does **not** change. The new words are display labels only, mapped in the UI copy files.
- Do not write commentary examples yourself beyond the single format example given below. The examples are Tyler's to write.

## Parts

1. **`docs/VOICE.md`** with these sections, written plainly (no em dashes, no lists of three for rhythm):
   - **Register:** live-text football commentary. Present tense. Short: one or two sentences, 30 words at most. Team before player. A number appears only when a fact supplies it.
   - **Adjectives are claims:** "against the run of play", "dominant", "fading", "in control" each need a fact behind them (possession, territory, shot share, line height). With no fact, cut the word.
   - **Modes:**
     - *fan:* what happened and why it matters.
     - *analyst:* the mechanism (shape, distances, sequences).
     - *producer:* a rundown note (clip window, angle, what to show), not commentary.
   - **Banned patterns:** a pointer to `voice/banned.yaml`, plus five before-and-after pairs. Use these two:
     - "In a dramatic turn of events, Ashford showcase their resilience." → "Ashford level it. Their first shot on target since the 30th minute."
     - "Rivermouth's press is not just aggressive but relentless." → "Rivermouth have won it back in Ashford's third six times since half-time."

     Write three more in the same spirit.
   - **On-screen verdict vocabulary:** map the schema verdicts to the display labels in the table below. The words "AI", "agent", "model" and "generated" never appear in the live desk UI; they are allowed in the dev panel, the docs and the pitch.

     | Schema verdict | Label | Meaning shown to the viewer |
     | --- | --- | --- |
     | `checking` | CHECKING | The pitch highlights the players or zone the claim is about |
     | `verified` | STANDS | The claim matches the evidence |
     | `rephrased` | AMENDED | Old wording struck through, new wording below, reason on hover |
     | `blocked` | OVERTURNED | The claim is withdrawn; the reason is shown |
     | `delayed` | HELD | Evidence not in yet; the claim waits |

   - **Visual rules:** no sparkle or magic icons, no gradients, no glow, no typing or streaming-cursor animation, no chat bubbles, no "Thinking…" spinners. While a claim is checking, show the evidence on the pitch instead of a spinner.
   - **Real-world references:** study real live-text and radio commentary for rhythm, but never paste real lines into the repo. Rewrite with fictional clubs, and mark them `source: adapted`.
2. **`voice/banned.yaml`**: a list of rules, each with `id`, `pattern` (a regex, case-insensitive, word-bounded where it makes sense), `severity` (`error` or `warn`), `applies_to` (any of `narration`, `ui`) and `why` (one line).
   - **Seed `error` rules:** em dash `—`; ` -- `; `not just .{1,40} but`; `showcas\w*`; `testament`; `delv\w*`; `seamless\w*`; `leverag\w*`; `unlock\w*`; `game.?changer`; `dramatic turn`; `it'?s worth noting`; `a masterclass in`; `tapestry`; `\bpivotal\b`; `in today'?s`; any emoji (Unicode `Extended_Pictographic`); exclamation mark (narration only).
   - **Seed `warn` rules:** `seems to|appears to` (hedging); a sentence of more than 30 words.
   - **UI-only `error` rules:** `\bAI\b`, `\bagent\b`, `\bgenerated\b`, `✨`.
3. **`packages/intel/src/intel/voice_lint.py`**
   - `load_rules(path=None) -> list[Rule]`, defaulting to the repo's `voice/banned.yaml`.
   - `lint(text, applies_to: Literal["narration", "ui"], rules=None) -> list[Violation]`, where `Violation` holds `rule_id`, `severity`, `start`, `end` and `excerpt`.
   - `numbers_in(text) -> list[str]` returns the numeric tokens in a string ("6", "8 m", "41′", "0.31"). The Checker's reconciler reuses it on Thursday.
   - **CLI:** `uv run python -m intel.voice_lint <paths…>` lints UI copy JSON files (every string value) and prints violations. It exits 1 on any `error`.
4. **`voice/examples.yaml`**: the Narrator's few-shot set. The sourced version (ex-01 to ex-15, each with `source: adapted` and a `source_ref` like `S07`) is already on `main`. Keep those entries unchanged and add this one entry, marked `format_only: true`, at the top. The `source_ref` field is optional; the shape test accepts `S` followed by two digits.
   ```yaml
   - id: ex-00
     format_only: true
     beat_kind: counter_goal
     mode: fan
     lang: en
     facts:
       - { id: fx-0001, display: "41′" }
       - { id: fx-0002, display: "11 seconds" }
       - { id: fx-0003, display: "4 passes" }
     line: "Ashford go 41 metres the other way and score. Eleven seconds, four passes, Rivermouth caught with both full-backs high."
     amended_from: null   # for AMENDED examples: the bad draft
     reason: null         # for AMENDED examples: why it was changed
     source: original     # original | adapted
   ```
   The format example is deliberately flawed: "41 metres" has no fact behind it, "both full-backs high" has no fact behind it, and "Eleven" is a number word. The test below must catch the first, so that the test proves itself. Note that in the header comment.
5. **UI copy files:** create `apps/web/src/copy/en.json` and `es.json` if they don't exist, holding at least the five verdict labels (Spanish: COMPROBANDO, VÁLIDO, CORREGIDO, ANULADO, EN ESPERA). Add the `voice_lint` CLI over `apps/web/src/copy/*.json` to `make lint`, and so to CI.
6. **Theme audit:** check `apps/web/src/theme/tokens.ts` and `docs/prototype/README.md` against the visual rules. Change token values only if a gradient, glow or purple accent exists. Either way, list what you found in the PR.

## Tests (in `packages/intel/tests/test_voice_lint.py`)

- Each seed rule fires on a positive case and stays quiet on a near-miss. For example, `not just` with no `but` within 40 characters passes, and "showcase" fires while "show" does not.
- UI-only rules don't fire on narration, and narration-only rules don't fire on UI copy.
- Every non-`format_only` entry in `examples.yaml` lints clean, with no `error` rules.
- **Numbers come from facts:** for every non-`format_only` example, each item in `numbers_in(line)` appears in `numbers_in` of at least one fact `display`.
  - Mark `ex-00` as an expected failure (`xfail`, strict), so a fix to it gets noticed.
  - Number words ("eleven") are out of scope for v1; note that.
- **Example shape:** `beat_kind` is in the beat schema enum, `mode` is in {fan, analyst, producer}, the line is 30 words or fewer, and AMENDED examples have both `amended_from` and `reason`.
- The copy files lint clean.
