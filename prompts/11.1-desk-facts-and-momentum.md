## Parts

1. **Running totals (Python).**
   - At the end of every 5-minute bucket of match time (5′, 10′, … and at each half's end), emit match-to-date facts for both sides: `possession_share`, `shots`, `shots_on_target` and `xg`.
   - Name them `<metric>(<side>, to <mm>′)`, for example `xg(home, to 70′)`.
   - Scope runs from 0 to the bucket end. Sources are the window or aggregate ids they sum, so the source chain stays intact.
   - Batch and incremental engines must agree. Extend the existing live-equals-batch test.
2. **Momentum (Python).**
   - One fact per 5-minute bucket, `momentum(min-NN)`, with buckets `min-01` to `min-18` (nine per half). The last bucket of each half (`min-09`, `min-18`) absorbs stoppage time.
   - Value: the home share minus the away share of attacking actions (final-third entries plus shots), in percentage points, from −100 to 100. Unit `pp`.
   - A bucket with no attacking actions has value 0 and still exists.
   - Emit each fact when its bucket closes.
   - Add a `momentum` template to `labels.py`.
   - Add `min-NN` to the ID conventions in `CLAUDE.md` in a separate one-line commit.
3. **Readable labels (schema and Python).**
   - Add an optional `label` (string) to `fact.schema.json`: "Plain-English label from intel.labels; for display only."
   - Fill it wherever facts leave Python for the desk, using `labels_for`: the SSE `fact` messages, the archive's `claim_graph.json`, and the fixture.
   - Fix the two raw time leaks at their source:
     - **on-demand fact names:** keep `t3103.99` in `name`, because it is the id contract, but render it as the broadcast clock (`51:43`) in `label`;
     - **aggregate descriptions:** in `since.py` / `last_minutes`, "up to match time 3103.99" becomes "up to 51:43" via `display.render_clock`.
   - Run `make gen`.
4. **Fixture.**
   - `make_desk_fixture.py` rebuilds the fact registry from the archived brief and events with the current `intel` (deterministic), adds labels, and keeps everything else.
   - Before writing, check that every fact id cited by the fixture's claims still resolves in the rebuilt registry. If any does not, stop and report it.
   - Replace `stat_windows` with `running` (the to-date fact ids per bucket) and `momentum` (the `momentum(min-NN)` fact ids in order).
   - Regenerate `apps/web/fixtures/desk.json` and keep it under 400 KB.
5. **Desk UI.**
   - **Stats panel:**
     - show the latest running-total facts at the clock, headed "Match · to 70′" (copy, en and es);
     - shots on target is the new third row; keep xG;

   - **Momentum strip** (`MomentumStrip`):
     - **Bars:** one thin bar per closed bucket, diverging from a `line` centre axis. Positive values rise in `home`, negative values drop in `away`, and zero draws a 2px tick on the axis. Bar height is the value over the largest absolute value so far, scaled to half the strip height. Gaps are 3px.
     - **Ticks:** 0′, 45′ and 90′ below the axis.
     - **Moment pins:** small markers on the axis at their minute (a 10px slanted chip in `chip` with `ink` text). Only the selected pin shows its label; the others show it on hover and focus, through `aria-label`. Pins never overlap at 390 px.

     - **Source events:** aggregate and window rows show their description with the clock, never the `agg-` id. The id moves to `title`.
