# Build prompt 14.1 — Trials scoring fixes, then the full pack

**Mode:** code, then run. **Budget:** 45 min of code, then the run (~75 min, unattended). **Branch:** `feat/narrator-trials` (same PR, #35). **Depends on:** PR 35 as it stands. **Blocks:** prompt 15 (Table and Compare).

## Why

Review of PR 35 found three scoring problems. All three change what the results file holds, so they go in before the full run, not after.

1. **Lost beats are unscored.** On fx-01, gpt-5-nano cited fact ids that don't exist on 3 beats. `put_claims` rejected them, the workflow raised `ValueError`, and the runner put the beat in `errors`, worth 0 pts. Inventing a citation is the worst thing a narrator can do. As it stands, a model that does it on every beat scores 0 and ranks above one that tries and gets −18. Candidates also end up scored on different numbers of moments.
2. **`p90_ms` is the referee's time, not the narrator's.** `run.latency_ms` covers draft, judge check, retry and re-check. That's why gpt-5-mini shows 9.2 s instead of ~2 s, and a model that needs more retries gets punished twice.
3. **Most overturns had only one referee.** The auditor only sees `verified`/`rephrased`. For nano, 10 of 15 scored claims were never audited, so its judge-caught overturns rest on gpt-5-mini alone, and gpt-5-mini is a rival candidate. Some of those calls look wrong (fx-01 89′, "Ashford Vale win it", was overturned as a team-level turnover).

## Fix 1 — Every beat gets exactly one scored row

In `play_fixture`, pass a small `DraftCapture` observer in `Deps(observer=...)`. It implements the three `Observer` methods and keeps `previews` by beat id, so a lost beat can still show what the narrator wrote. It must not change behaviour: `decided` and `settled` do nothing.

When a beat produces no checked claim, write one **scored** stand-in row, using `previews[0]` for `id`, `text`, `draft_text` and `fact_ids` when there is one. Otherwise use id `cl-<beat stem>-01`, empty text and no facts. Set the new `lost` field:

| case | how it shows | `lost` | verdict | bucket | reasons |
| --- | --- | --- | --- | --- | --- |
| store refused the claims | `ValueError` starting `put_claims rejected claims:` | `rejected` | OVERTURNED | `citation` if any error starts `Unknown fact id`, else `other` | each store error, parsed with `ast.literal_eval` from the message |
| output unreadable | `run.error == "Narrator: StructuredOutputError"` | `unreadable` | OVERTURNED | `other` | "The Narrator's output could not be read as claims." |
| narrator wrote nothing | no error, no checked claims | `no_claim` | OVERTURNED | `other` | "The Narrator wrote no claim for this beat." |
| model call failed | `run.error == "Narrator: LlmError"`, or `LlmError`/`OSError` raised | `no_answer` | HELD | null | the error name |

Keep appending to `errors` as now, so the audit trail stays. Stand-in rows have `latency_ms: null`, `narrator_ms: null`, tokens 0, `auditor: "not audited"`, `referee_split: null`.

**Rule:** timeouts and 429s are our infrastructure, so HELD (unscored). Everything the model did wrong costs points.

## Fix 2 — Narrator latency is its own column

- Per claim, `narrator_ms = run.narrator_calls[0].latency_ms` (the first draft, parse retries included); `latency_ms` stays the beat's on-air time.
- `FixtureRun` keeps two lists: `narrator_latencies` and `on_air_latencies`.
- Summary: `p90_ms` is now the narrator p90; add `on_air_p90_ms`. Ranking ties still break on `p90_ms`.

## Fix 3 — Second referee on judge-only overturns (log-only)

In `settle`, a claim that is `blocked` where **every** reason in `checked.final.reasons` starts with `JUDGE_REASON_PREFIX` (the judge alone caught it, no code check) is also audited. That's one `auditor.audit(...)` call under the same `gate`. No consensus, and the verdict never changes.

- `referee_split = True` when the audit outcome is `agree` (the auditor finds it supported, so it would have let it stand); `False` when `disagree`; null when `unavailable` or not applicable.
- The `auditor` label on these rows reads `supports` or `confirms (<problem>)`, not `agree`/`disagree`, because the meaning is inverted on an overturned claim.
- `audit_agreement` counts settled-claim audits only. Exclude rows where `referee_split` is not null.
- Summary adds `double_checked` (scored rows with `referee_split` not null) and `referee_splits` (of those, `True`).
- Markdown: add `Split` (`referee_splits/double_checked`) and `On-air p90` columns. Mark each OVERTURNED line with `[split]` where `referee_split` is true.

## Tests (add to `tests/test_trials.py`)

- A rejected beat with an `Unknown fact id` error becomes one scored OVERTURNED `citation` row, using the captured preview's text.
- `Narrator: StructuredOutputError` → OVERTURNED `other`, `lost: unreadable`. `Narrator: LlmError` → HELD, `lost: no_answer`.
- **Equal denominators:** two fake candidates on the same fixture, one with a rejected beat and one clean, have the same `claims` count.
- `p90_ms` comes from `narrator_ms`, `on_air_p90_ms` from `latency_ms`.
- A judge-only blocked claim with audit `agree` gives `referee_split: true` and `auditor: "supports"`. One with a code reason (numbers) is not double-checked.
- `audit_agreement` ignores double-check rows.
- Fix the existing `test_summary_maths` for the new signature and fields.

`make lint typecheck test check-contracts` all exit 0.
